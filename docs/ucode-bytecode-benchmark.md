# ucode: замеры по предложению №79

Проверка: [GitHub CI, 19.10.2026](https://github.com/petrouspetr-pixel/trafira/actions/runs/39256893943).

Сравнивались временные копии 109 модулей backend: уплотнённый текст и байткод без отладочных данных, собранный тем же ucode `v0.0.20250529`, которым он затем запускался. Установленные файлы не изменялись.

| Показатель | Исходники | Байткод |
| --- | ---: | ---: |
| Объём модулей, байт | 1 750 577 | 1 478 708 |
| gzip объединённого содержимого, байт | 359 777 | 429 719 |
| Медиана запуска, мс | 8,144 | 2,206 |
| Максимальный RSS процесса, КиБ | 3 252 | 2 868 |

Выполнялась команда `diagnostics/runtime.uc show-version`, 15 запусков каждого варианта с прогретым файловым кэшем ОС. Вывод вариантов совпал. RSS измерялся через `/usr/bin/time`; размер gzip — оценка сжимаемости содержимого, не размер APK/IPK.

Это замер на Linux runner GitHub, а не на роутере. Он подтверждает пользу устранения разбора исходников при запуске, но не устанавливает причину задержек всей страницы LuCI. Он также не проверяет совместимость байткода между версиями ucode/OpenWrt.

Повторение в Linux со сборщиком ucode и `/usr/bin/time`:

```sh
python3 tools/benchmark-ucode.py --report /tmp/trafira-bytecode-benchmark.json
```

Результаты сохраняются артефактом Backend CI вместе с отчётом размера установленного backend. Бенчмарк и этот документ не входят в пакеты Trafira.
