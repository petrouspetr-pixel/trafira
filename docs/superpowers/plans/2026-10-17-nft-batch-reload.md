# Пакетное применение nftables и повторные reload

Утверждённый пользователем объём: оптимизировать применение nftables, устранить лишние повторные применения, сохранить порядок маршрутизации; без релиза и установки на роутер.

1. Тестами зафиксировать отложенное атомарное применение команд, их порядок, отказ при переполнении и ошибке nft. Проверить различие между служебной сериализацией UCI и реальными правками пользователя.
2. Добавить ограниченную транзакцию nft: подготовка без изменения рабочей таблицы, удаление и создание таблицы одним `nft -f`, публикация сопутствующего состояния только после успеха. Объединить команды добавления элементов.
3. Использовать общую нормализацию UCI для проверки повторного reload и сохранения применённого checkpoint; сохранить порядок секций и списков, не игнорировать пользовательские значения.
4. Сравнить последовательность правил до/после на одинаковой конфигурации. В изолированном network namespace проверить действительные nft-транзакции, сохранение старой таблицы при ошибке и маршруты пакетов.
5. Запустить все backend-тесты на исходных и компактных файлах, сетевые проверки и обязательные проверки PR. Результаты измерений не переносить на производительность физического роутера без замера на нём.
