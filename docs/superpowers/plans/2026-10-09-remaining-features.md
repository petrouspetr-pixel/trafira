# Remaining Trafira Features Implementation Plans

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution or superpowers:subagent-driven-development if the user chooses delegated execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать шесть согласованных функций, сохранив старое поведение до их включения.

**Architecture:** Шесть последовательно интегрируемых подсистем используют текущие UCI, генератор, обновление компонентов и контроллер приоритетных подключений. Диагностика не меняет состояние; изменяющие операции используют единый порядок блокировок и восстановление.

**Tech Stack:** ucode v0.0.20250529, sing-box, nftables, LuCI JS, TypeScript/Vitest, Bash/Node tests, GitHub Actions.

**Spec:** [Согласованный проект](../specs/2026-10-09-remaining-features-design.md), одобрен пользователем 9 октября 2026 года.

## Global Constraints

- «Релиз и установка на роутер — отдельные действия.»
- «Новые возможности не меняют старое поведение до явного включения».
- «Пароль, ключи и URL с токенами не попадают в отчёты».
- «IPv4 и IPv6 проверяются отдельно».
- «Интеграция только в petrouspetr-pixel/trafira, без комментариев и PR в upstream».
- Источник требований — согласованный проект; новый код не копируется из чужих форков без проверки поведения и лицензии.
- Названия: Alice Mode, дашборд, «Профили настроек», «Куда пойдёт соединение?».

## Review Focus

1. Неизвестное раннее правило или обход Alice Mode не должны превращаться в уверенный, но неверный ответ диагностики: план 1, задачи 1–2.
2. Аварийное завершение или одновременное обновление не должны уничтожить исходную конфигурацию: план 2, задача 2; план 3, задача 2.
3. Неудачная проверка самого механизма контроля не означает разрешение direct: план 4, задачи 1–2.
4. Перехват соединений самого роутера не должен захватить транспорт VPN и bootstrap DNS: план 5, задача 1.
5. Общие игровые CDN и смена адреса устройства не должны включить обход для всей сети: план 6, задачи 1–2.

## Подготовка выполнения

- [ ] Прочитать выбранный навык выполнения и using-git-worktrees; переиспользовать подходящую изолированную рабочую копию. Сначала сохранить документацию, не затрагивая сторонние изменения.
- [ ] Зафиксировать исходный SHA и состояние origin/main, выполнить исходные проверки frontend. Не запускать release workflow.
- [ ] Для backend использовать Linux с ucode указанной версии. В Windows запуск shell-теста без ucode не считается проверкой. Допустимо выполнять красный/зелёный цикл в отдельном Linux CI, добавив временный ручной запуск тестов без публикации артефактов.
- [ ] До любого изменения nft сверить текущие первичные документы sing-box для поддерживаемых веток; версия и конкретные возможности проверяются отдельно. Новую зависимость не устанавливать на физический роутер пользователя.

## Integration Gate — повторить после каждого дочернего плана

- [ ] Добавить конкретные новые подписи в `luci-app-trafira/po/ru/trafira.po`, обновить `README.md` с пользовательским сценарием, ограничениями и способом отмены. Не добавлять миграцию Podkop/Forkop.
- [ ] Из `fe-app-trafira` выполнить:

```sh
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc --noEmit
node node_modules/eslint/bin/eslint.js src --ext .ts,.tsx --max-warnings=0
node node_modules/prettier/bin/prettier.cjs --check src
node node_modules/tsup/dist/cli-default.js src/main.ts
```

- [ ] В Linux проверить ucode и весь backend так же, как `.github/workflows/backend-ci.yml`:

```sh
find trafira/files/usr/lib -name '*.uc' -print0 | xargs -0 -n1 ucode -c -o /dev/null
find trafira/files/usr/lib -name '*.uc' -print0 | xargs -0 -n1 ucode -S -c -o /dev/null
printf '%s\0' tests/*.sh | xargs -0 -n1 -P4 bash -c 'bash "$1"' _
git diff --check
```

- [ ] Повторная сборка frontend не меняет результат. Сгенерированный `LUCI/main.js` входит в тот же коммит, что исходники. Не считать старые зелёные CI проверкой нового SHA.
- [ ] Просмотреть полный diff на секреты, широкий доступ RPC, неограниченные операции и побочные изменения. Проверить новые backend-тесты фактическим исполнением, а не поиском строки в исходнике.
- [ ] Commit → push в собственный fork → PR → прикрепление PR к чату → зелёные Backend CI и Differential ShellCheck → рассмотрение и устранение замечаний → merge → проверка main. Без релиза и без изменений физического роутера.

## Статус

Реализованы все шесть этапов в PR [#19](https://github.com/petrouspetr-pixel/trafira/pull/19). Итоговое ревью выявило пять существенных дефектов; для них сначала воспроизведены ошибки, затем внесены исправления и повторно пройдены проверки. Дополнительно проверяется отказ публикации снимка применённых настроек.

Проверки включают 545 тестов frontend, проверку типов и стиля, воспроизводимую сборку LuCI, обычную и строгую компиляцию ucode, весь набор backend-тестов, Differential ShellCheck и отдельные сетевые сценарии IPv4/IPv6 с восстановлением после аварийного завершения. Актуальное состояние интеграции и проверок последнего коммита доступно в PR. Релиз и установка на физический роутер в этот план не входят.
