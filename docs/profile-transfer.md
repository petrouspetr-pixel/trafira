# Перенос настроек Trafira

## Перед переездом

1. В **Профили** сохраните нужные изменения формы и создайте профиль. Выберите его и нажмите **Проверить зависимости**. Отчёт сравнивает профиль с текущим роутером, не меняя настройки и не создавая архив.
2. Нажмите **Экспорт профиля** и сохраните JSON в защищённом месте. Он содержит настройки всех секций, подписок, URLTest и Priority, включая сохранённые пароли и ключи. Не публикуйте его в Issues.
3. Отдельно сохраните внешние файлы из отчёта: сертификаты, закрытые ключи, локальные списки. JSON хранит пути к этим файлам, а не их содержимое. Даже найденный файл понадобится перенести на другой роутер. Ссылки неактивных настроек показаны отдельно: они могут понадобиться позже.
4. Запишите версии Trafira и sing-box, вариант ядра, необходимые компоненты и архитектуру нового устройства. Отчёт показывает найденные исполняемые файлы и доступные номера версий; это не проверка исправности пакетов. Заранее скачайте совместимые пакеты из доверенного источника, если после переезда интернет может быть недоступен. Профиль не содержит пакеты и зависимости системы.

**Проверка зависимостей** ищет известные пути к сертификатам/ключам, локальным rule sets и доменным/IP-спискам, проверяет наличие sing-box и используемых DPI-компонентов. Для распознанных XHTTP, MTProto и native fallback отмечается необходимость Extended. Содержимое внешних файлов не читается. Ссылки подписок, пароли, значения ключей и имена частных секций в отчёт не включаются; сами пути могут быть приватными, поэтому отчёт доступен только администратору.

Произвольный JSON и пользовательские стратегии могут содержать другие зависимости. Ограничения разбора и ошибки JSON обозначаются явно. Отчёт не проверяет доступность удалённых списков, действительность сертификатов, все возможности конкретной сборки sing-box или реальные соединения. Перед применением профиля Trafira отдельно проверяет конфигурацию.

## Подписки и HWID

Явно заданные User-Agent, HWID и заголовки сохраняются в профиле вместе с настройками подписки. Автоматический HWID зависит от MAC-адреса и модели роутера: на другом устройстве он может измениться. Если провайдер привязывает подписку к устройству, заранее уточните перенос или задайте согласованный постоянный HWID. Не переносите случайные файлы кэша вместо настроек подписки.

## Восстановление в Trafira

1. Установите совместимые Trafira и компоненты. Создайте нужные сетевые интерфейсы OpenWrt отдельно: они не входят в профиль Trafira.
2. Верните внешние файлы по указанным абсолютным путям. Закрытые ключи должны быть доступны службе и защищены от чтения посторонними.
3. Импортируйте JSON через **Профили**, выберите его и снова нажмите **Проверить зависимости** уже на новом роутере. Затем нажмите **Применить профиль**. Кнопка **Показать различия** необязательна.
4. Проверьте запуск служб, DNS, маршруты, работу выбранных подключений и обновление списков. Совпадение путей и наличие бинарников сами по себе не подтверждают работоспособность всей конфигурации.

`/etc/config/trafira` — исходная конфигурация UCI; `/etc/trafira/profiles` — сохранённые JSON-профили. Файл `/etc/sing-box/config.json` сгенерирован Trafira и не заменяет полный профиль. Сгенерированные nftables, рабочие задания и кэши в RAM пересоздаются. Путь к кэшу sing-box задаётся настройками; такой кэш не является переносимой резервной копией конфигурации.

## Переход на другой проект

Экспорт — формат Trafira, а не универсальный импорт для Podkop, Forkop или других программ. Проверьте поддержку Priority, игровых пресетов, правил устройств, политик отказа и действий сторонних компонентов. Неподдерживаемые возможности нужно настроить вручную; простая замена имени пакета не выполняет миграцию.

Остановите старую службу перед включением нового владельца DNS и firewall. Проверьте DHCP/DNS OpenWrt, задания cron, watchdog, внешние скрипты и локальные патчи: профиль Trafira не переносит их автоматически. После переключения проверьте DNS и трафик устройств, включая IPv6 при его использовании.

Мастер удаления Trafira сохраняет настройки по умолчанию. Его `settings.tar.gz` охватывает `/etc/config/trafira*` и `/etc/trafira`, но не произвольные файлы в других каталогах. Это отдельный архив, который может содержать секреты; кнопка **Проверить зависимости** его не создаёт.

Администратор также может получить JSON-отчёт командой `/usr/bin/trafira-config profile_action '{"action":"dependencies","id":"ID_ПРОФИЛЯ"}'`. ID берётся из ответа `profile_action '{"action":"list"}'`; имя профиля и его ID — разные значения.
