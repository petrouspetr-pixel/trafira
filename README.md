# Trafira

**Управление трафиком, прокси и DNS на OpenWrt через LuCI.**

[![Backend CI](https://github.com/petrouspetr-pixel/trafira/actions/workflows/backend-ci.yml/badge.svg)](https://github.com/petrouspetr-pixel/trafira/actions/workflows/backend-ci.yml)
[![Releases](https://img.shields.io/github/v/release/petrouspetr-pixel/trafira?label=releases)](https://github.com/petrouspetr-pixel/trafira/releases)
[![License](https://img.shields.io/badge/license-GPL--2.0-blue)](LICENSE)

Trafira — независимое продолжение [Forkop](https://github.com/ushan0v/forkop), созданного на основе [Podkop](https://github.com/itdoginfo/podkop). Проект объединяет управление sing-box, правила маршрутизации, проверку доступности узлов и настройку DNS в одном интерфейсе OpenWrt.

В этой ветке развития собраны исправления сообщества и добавлена поддержка DoH с клиентскими сертификатами. Исходники, обсуждения и дальнейшие обновления находятся в этом репозитории.

## Возможности

- Подписки, отдельные прокси и интерфейсные подключения, в том числе через настроенный AWG-интерфейс.
- Маршрутизация по доменам, IP-адресам, устройствам и другим условиям; каскадные подключения и Bypass.
- Alice Mode: выбор устройств, которые используют Trafira или подключаются напрямую, с отображением маршрута в панели устройств.
- URLTest и группы с приоритетами, автоматическое переключение при недоступности узла.
- DoH, DoT и обычный DNS, резервные DNS-серверы, отдельные DNS для выбранных доменов и DNS через прокси.
- sing-box extended и XHTTP; опциональный native fallback на поддерживающих его сборках extended.
- Zapret, Zapret2 и ByeDPI как действия секций.
- Мониторинг соединений, диагностика и управление компонентами через LuCI.

## Alice Mode — выбор устройств

Начиная с **2.1.0**, в LuCI → Trafira → Alice Mode можно выбирать, какие устройства используют правила Trafira. По умолчанию режим выключен, поэтому существующая маршрутизация сохраняется.

- **Use Trafira**: устройства из списка используют Trafira, остальные подключаются напрямую.
- **Bypass Trafira**: устройства из списка подключаются напрямую, остальные используют Trafira.

Устройства можно указать по IPv4/IPv6, подсети, MAC-адресу или входящему сетевому интерфейсу. Для интерфейсов поддерживается маска с завершающим `*`, например `wg*`. Достаточно совпадения с одним из условий. Интерфейс также должен быть выбран в настройке исходных сетевых интерфейсов Trafira.

Включите режим, выберите поведение списка, добавьте устройства и сохраните настройки. Пустой список **Use Trafira** направляет все устройства напрямую; пустой **Bypass Trafira** оставляет все устройства в Trafira. Панель устройств показывает LAN-клиентов и WireGuard peers, выбранный маршрут и причину совпадения. Для обходящих Trafira клиентов DNS возвращает реальные адреса вместо FakeIP.

Alice Mode управляет маршрутизацией и не заменяет правила безопасности межсетевого экрана. Для LAN-клиентов с меняющимся IP удобнее MAC-адрес; для клиентов за маршрутизируемым туннелем используйте IP/подсеть или интерфейс.

## Запуск при недоступном источнике списков

Начиная с Trafira 3.0.0 для sing-box 1.14 и новее доступен постоянный кеш удалённых rule-set в `/etc/trafira/ruleset-cache`. Он наполняется при фоновом обновлении списков после успешного запуска. При следующем запуске sing-box может использовать проверенный снимок, даже если выбранный прокси или источник списков временно недоступен. Удалённые списки продолжают обновляться штатно, а настройки загрузки через прокси сохраняются.

На первом запуске или после смены URL списка, когда снимка ещё нет, доступ к источнику необходим. Повреждённая загрузка не заменяет рабочую копию. Кеш ограничен 8 МиБ, отдельный файл — 4 МиБ; при записи сохраняется минимум 4 МиБ свободного места. Неизменившиеся файлы повторно во flash не записываются. Отключение планового обновления списков отключает и плановое обновление снимков.

## Новые инструменты в Trafira 3.0.0

В Trafira 3.0.0 доступны:

- **Торренты напрямую.** Отдельная настройка отправляет распознанные соединения BitTorrent напрямую, минуя прокси и правила разделов. По умолчанию выключена. Распознавание не охватывает гарантированно весь трафик торрент-клиента: зашифрованные соединения и HTTPS-трекеры могут не определяться как BitTorrent. Для полного обхода на отдельном устройстве используйте Alice Mode.
- **Wi-Fi Calling напрямую.** Отдельная настройка исключает UDP-соединения на порты 500 и 4500 из перехвата Trafira для IPv4 и IPv6. Это помогает операторам, использующим IPsec для звонков через Wi-Fi. Остальные правила межсетевого экрана продолжают действовать; адреса FakeIP не отправляются напрямую. По умолчанию выключена.
- **Предпросмотр фильтров серверов.** Проверяет ещё не сохранённые фильтры на закешированных кандидатах текущего раздела: показывает количество оставшихся серверов и исключённые имена. Не скачивает подписку, не сохраняет настройки и не перезапускает службу. После изменения источника подписки сначала обновите его кеш; предпросмотр не предсказывает содержимое нового источника.
- **Панель сохранённых списков.** В диагностике можно посмотреть наличие, размер и дату снимков удалённых rule-set, а также запустить их подготовку в фоне. Подготовка сохраняет выбранный способ загрузки и ограничения места, не перезапускает службу. Наличие файла и ссылка на него в конфигурации показываются отдельно; при запуске содержимое снимка проверяется повторно.

## Установка одной командой

Первый релиз с новым системным именем — **Trafira 2.0.0**. Пакеты называются `trafira`, `luci-app-trafira` и `luci-i18n-trafira-ru`. Конфигурация хранится в `/etc/config/trafira`, постоянные данные — в `/etc/trafira`, служба — `/etc/init.d/trafira`.

Подключитесь к OpenWrt по SSH от root и выполните:

```sh
wget -O /tmp/trafira-install.sh https://raw.githubusercontent.com/petrouspetr-pixel/trafira/main/install.sh && sh /tmp/trafira-install.sh
```

Команда запускает установщик только после успешной загрузки. Он выбирает последний опубликованный релиз **из этого репозитория**, определяет `opkg` или `apk` и устанавливает соответствующие пакеты. После установки откройте **LuCI → Trafira**; при обновлении страницы может потребоваться очистка кэша браузера.

### Переход с Forkop / Podkop / Podkop Plus

Автоматического переноса настроек нет. Сохраните резервную копию настроек и нужных данных вне роутера, самостоятельно удалите пакеты прежнего проекта, затем установите Trafira и восстановите настройки вручную. Установщик останавливается при обнаружении старых пакетов; он не переносит и не удаляет их конфигурацию, данные или состояние Tailscale.

Не используйте `--force-depends` или снятие конфликтов для одновременного запуска Trafira и старой службы.

### Обновление без LuCI

Начиная с 3.0.3 встроенный компонент WARP исключён из проекта. Если вы установили его в 3.0.0–3.0.2, сначала снимите привязки его интерфейса в секциях Trafira и выполните `/usr/bin/trafira component_action warp remove` на прежней версии. Обновление несовместимо с установленным `luci-app-trafira-warp`. Настроенные вручную интерфейсы WireGuard/AmneziaWG по-прежнему поддерживаются.

Перед установкой компонентов через LuCI Trafira проверяет свободное место: минимум 32 МиБ для sing-box (8 МиБ для tiny) и 8 МиБ для остальных компонентов. Это минимальный запас, а не гарантия, что любой пакет поместится. Для распакованных файлов compressed-варианта дополнительно проверяется их полный размер с запасом 4 МиБ. При нехватке места операция останавливается до изменения пакетов и служб; ошибка установки сообщает о нехватке места или проблеме зависимостей, если пакетный менеджер указал такую причину. Храните резервные копии вне роутера.

**Рекомендуемый способ по SSH:** повторно выполните команду установки выше. Она обновляет пакеты из актуального релиза; переносить настройки вручную не требуется.

**Установка скачанных пакетов вручную** предназначена для уже установленной Trafira. Скачайте из [одного релиза](https://github.com/petrouspetr-pixel/trafira/releases) backend, LuCI и, если используется русский интерфейс, перевод той же версии. Выберите `.ipk` для `opkg` или `.apk` для `apk`. Скопируйте файлы в отдельный каталог `/tmp/trafira-update` на роутере.

Перед обновлением сохраните конфигурацию и постоянные данные, включая клиентские сертификаты; перенесите копию с роутера:

```sh
backup="/root/trafira-backup-$(date +%Y%m%d-%H%M%S).tar.gz"
tar -czf "$backup" /etc/config/trafira /etc/trafira
```

Для **3.0.0 с `opkg`** (в будущих обновлениях замените номер во всех именах файлов):

```sh
opkg update && opkg install /tmp/trafira-update/trafira_3.0.0.ipk /tmp/trafira-update/luci-app-trafira_3.0.0.ipk /tmp/trafira-update/luci-i18n-trafira-ru_3.0.0.ipk
```

Для **3.0.0 с `apk`**:

```sh
apk update && apk add --allow-untrusted /tmp/trafira-update/trafira_3.0.0.apk /tmp/trafira-update/luci-app-trafira_3.0.0.apk /tmp/trafira-update/luci-i18n-trafira-ru_3.0.0.apk
```

Параметр `--allow-untrusted` нужен для самостоятельно собранных APK, не подписанных ключом официального репозитория OpenWrt. Используйте файлы из нашего релиза. Если перевод не установлен и не нужен, исключите третий пакет из команды. Не смешивайте версии backend и LuCI.

После успешного завершения обновления перезапустите службу, если она была включена, и проверьте журнал:

```sh
/etc/init.d/trafira enabled && /etc/init.d/trafira restart
logread -e trafira
```

При ошибке установки сначала исправьте её; не удаляйте конфигурацию и резервную копию. Пакетный менеджер сохраняет пользовательскую конфигурацию; после обновления также проверьте возможные файлы `.opkg-dist` / `.apk-new`.

### Источник обновлений

Вкладка обновлений LuCI и установщик используют [релизы petrouspetr-pixel/trafira](https://github.com/petrouspetr-pixel/trafira/releases). Сторонние компоненты (sing-box, Zapret и другие) обновляются из своих репозиториев.

Сборка пакетов описана в [build.sh](build.sh) и [workflow сборки](.github/workflows/build.yml). Возможности зависят от установленной версии sing-box и дополнительных компонентов.

## Где хранится кэш sing-box

По умолчанию кэш находится в RAM: `/tmp/sing-box/cache.db`. Если нужно сохранять его между перезагрузками, в настройках выберите **Flash (/etc/sing-box/cache.db)**. Это расходует место и увеличивает записи во flash. Ранее сохранённые и вручную введённые пути остаются действующими; обновление не переносит существующую базу автоматически.

## Настройка DoH с mTLS

mTLS нужен только тогда, когда DoH-сервер требует клиентский сертификат. Персональный путь или токен в URL сами по себе mTLS не требуют.

1. Получите клиентский сертификат и соответствующий закрытый ключ, которым доверяет ваш DoH-сервер. Разместите их на роутере, например в `/etc/trafira/dns/client.crt` и `/etc/trafira/dns/client.key`. Ограничьте доступ к закрытому ключу; процесс sing-box должен иметь возможность прочитать файлы.
2. В **Trafira → Настройки** выберите **DNS over HTTPS (DoH)** и добавьте полный URL, например `https://dns.example.net:8443/dns-query`.
3. Включите **«Аутентификация DoH клиентским сертификатом»**.
4. В поле **«Имя хоста для сертификата DoH»** укажите `dns.example.net` — без протокола, порта и пути.
5. Укажите абсолютные пути к сертификату и ключу и нажмите **«Сохранить и применить»**.

LuCI принимает пути к уже существующим файлам; загрузки сертификатов через эту форму пока нет. Сертификат используется только для совпадающего основного DoH-хоста и его проверок доступности. Bootstrap DNS и другие хосты его не получают. Если настроен резервный DNS другого хоста, он работает со своей обычной аутентификацией.

Проверки конфигурации контролируют хост, протокол и формат путей. Наличие и корректность файлов, доверие сертификату и успешное TLS-соединение нужно проверить на целевом устройстве.

## Выбор версии sing-box

В **Обновления → Версии sing-box** можно выбрать доступную версию уже установленного варианта, в том числе более старую, и закрепить её. Для stable/tiny используются версии из репозитория пакетов OpenWrt, для extended — совместимые стабильные сборки его проекта. Список кэшируется на 15 минут; перед установкой наличие выбранной сборки проверяется заново.

До замены проверяются архитектура, пакет, опубликованная контрольная сумма и совместимость с сохранённой конфигурацией. Предыдущие пакеты подготавливаются для восстановления без сети. Если проверка или запуск не удались, выбранная версия не закрепляется. Установка выполняется в фоне; закрытие страницы не прерывает её.

Закрепление действует только для обновлений через Trafira. Для смены варианта sing-box сначала снимите закрепление. Установка вручную через `apk` или `opkg` не подчиняется этому ограничению.

## Профили настроек

В **Диагностика → Профили настроек** можно сохранить текущие настройки Trafira, сравнить их с сохранённым профилем, применить профиль или вернуться к предыдущим настройкам. Поддерживается до восьми профилей размером до 1 МиБ каждый. Сохраняются только уже записанные настройки; незавершённые правки в формах LuCI в профиль не входят.

Профили не включают настройки сети и firewall OpenWrt, установленные пакеты, списки и файлы сертификатов. Перед применением Trafira проверяет конфигурацию установленным sing-box и наличие используемых интерфейсов и файлов. Если проверка не пройдена, текущие настройки остаются на месте. Неудачный запуск вызывает восстановление; результат восстановления показывается отдельно. Остановленная служба не запускается автоматически при применении профиля.

Применение продолжается после закрытия страницы или разрыва SSH. При аварийном завершении незаконченная замена восстанавливается перед следующим запуском Trafira. Кнопка **«Восстановить предыдущие настройки»** доступна отдельно от восьми пользовательских профилей.

Импорт и экспорт используют JSON. Экспортированный файл содержит учётные данные: храните его в защищённом месте. Значения параметров не выводятся в сравнении. Управление профилями требует прав на изменение настроек Trafira. Для просмотра списка через SSH: `trafira-config profile_action '{"action":"list"}'`.

## Поддержка и разработка

### Проверка маршрута соединения

В **Диагностика → Куда пойдёт соединение?** укажите домен, устройство, порт и протокол. Для ручного ввода можно добавить входящий интерфейс, MAC и реальный IP назначения. Результат относится к применённой конфигурации: показывает порядок правил, первый найденный маршрут и перекрытые правила. Для неизвестных условий выводится «Недостаточно данных».

Проверка не меняет настройки, не переключает узлы и не отправляет запросы от имени выбранного устройства. Удалённые списки, которые sing-box не экспортирует в доступные локальные файлы, отмечаются как недоступные для точного анализа; сохранённая стартовая копия не выдаётся за текущий список ядра. После обновления пакета происхождение правил появится при следующем обычном применении настроек. Анализ трафика самого роутера требует поддержки отдельного исходящего маршрута. Сохранённые, но ещё не применённые настройки Alice Mode не меняют результат диагностики. Если снимок применённых настроек недоступен, служба остановлена или введён FakeIP вместо реального адреса назначения, выводится «Недостаточно данных».

Сообщайте о проблемах в [Issues Trafira](https://github.com/petrouspetr-pixel/trafira/issues), а изменения предлагайте через [Pull Requests](https://github.com/petrouspetr-pixel/trafira/pulls). Прикладывайте версии OpenWrt, Trafira и sing-box, шаги воспроизведения и относящиеся к проблеме логи. Удаляйте из них пароли, приватные ключи и персональные URL подписок или DNS.

Перед объединением изменений выполняются проверки backend на ucode, shell-тесты, ShellCheck, тесты frontend, проверка форматирования и сборка интерфейса. Эти проверки дополняют, но не заменяют испытания на реальном роутере.

### Поведение при отказе VPN

В секции подключения можно оставить прежнее поведение, блокировать трафик при отказе, выбрать резервную секцию либо явно разрешить прямой выход без VPN. Для существующих настроек ничего не меняется. По умолчанию переключение требует трёх последовательных неудач, возврат — двух успехов, а между переключениями выдерживается не менее 30 секунд. Ошибка проверки сама по себе не разрешает прямой выход.

На дашборде отображаются основное, резервное или прямое подключение, блокировка и время с последнего переключения. При включённой политике запуск начинается с блокировки до подтверждения доступности. Переключение прерывает открытые соединения. Защита действует только во время работы Trafira; после неудачного применения временная защитная блокировка сохраняется до успешного восстановления или явной остановки/перезапуска сервиса. DNS-сопоставление по адресным спискам может требовать защищённого DNS-запроса ещё до определения подходящей секции; при недоступности такого пути ответ не выдаётся через прямой DNS.

При обычном применении настроек с политикой отказа или маршрутизацией приложений роутера сохраняется последняя рабочая конфигурация. Ошибка применения вызывает восстановление. На время перестроения firewall временно блокируется пересылаемый трафик всех управляемых интерфейсов, включая секции без политики отказа; доступ к управлению роутером сохраняется. При неудачном восстановлении блокировка остаётся до устранения ошибки и успешного запуска. Для такого применения необходим снимок предыдущего успешного запуска Trafira.

### Трафик самого роутера

В настройках «Маршрутизация приложений роутера» выбирается включённая секция подключения. По умолчанию функция выключена. Она управляет оставшимися исходящими TCP/UDP-соединениями локальных программ; маршруты LAN, явно выбранные служебные транспорты и обработка Zapret сохраняются. Действует политика отказа выбранной секции.

Исключения: ответы входящим соединениям управления, loopback и локальные сети, DHCP, настроенные адреса bootstrap DNS/NTP, служебные соединения с метками и активные системные транспорты WireGuard/AmneziaWG. Для native VPN сейчас поддерживаются только интерфейсы WG/AWG, чьи сокеты удалось обнаружить; неизвестный транспорт запрещает включение. Адреса исключений проверяются перед применением и обновляются при пересоздании правил после сетевых событий. NTP-серверы должны разрешаться через рабочий bootstrap DNS. Порт 1605 зарезервирован под отдельные входы роутера. Для диагностики маршрута выберите «Этот роутер» и укажите IP назначения: без адреса нельзя достоверно проверить исключения до прокси.

### Игровые пресеты для выбранного устройства

В «Диагностике» доступны редактируемые пресеты Steam, PlayStation, Xbox и Epic Games: известные домены магазина и учётной записи через выбранное подключение, остальной трафик **только явно выбранных адресов устройства** напрямую. Выберите устройство, его IPv4/IPv6-адреса и приоритет относительно существующих правил, затем откройте предпросмотр. Проверяются текущая конфигурация, генерация sing-box и конфликты Alice Mode; применение использует транзакцию с восстановлением. После закрытия страницы состояние применения можно проверить при повторном открытии.

Это исходные списки веб-сервисов, а не гарантия полного покрытия каждой консоли или игры. Общие домены могут обслуживать и магазин, и игровой сеанс; неперечисленные адреса выбранного устройства пойдут напрямую. [Источники и ограничения каталога](docs/gaming-presets-sources.md). DHCP и временные IPv6-адреса требуют повторного просмотра и обновления правил. Пресеты не открывают входящие порты, не включают UPnP и не создают общий обход UDP.

Созданные правила можно редактировать обычным способом. Повторное применение не создаёт копии; замена ручных правок требует отдельного выбора и предпросмотра. При удалении можно оставить правила как обычные. Обновление пакета или каталога само по себе не переписывает ранее созданные правила. Если Alice Mode исключает устройство, мастер предлагает включить только выбранные адреса; широкое исключение для подсети, интерфейса или MAC нельзя удалить автоматически, затронув другие устройства.
