# Пользовательские правила NFQUEUE

Проверка NFQUEUE обычно считает любое правило вне `table inet TrafiraTable`,
пересекающее диапазон очередей провайдера, конфликтом. Для отдельного
пользовательского правила, которое намеренно направляет пакеты тому же
управляемому Trafira процессу, можно задать **точный** комментарий:

```nft
meta l4proto tcp ct mark & 0x00020000 == 0x00020000 ct reply packets 1-15 counter queue flags bypass to 4300 comment "trafira-ignore"
```

Это пример строки внутри уже подготовленной пользователем цепочки fw4.
Значения conntrack mark, фильтров и номера очереди необходимо согласовать
со своей конфигурацией. Сам маркер не создаёт цепочку, не настраивает
conntrack mark, не запускает nfqws2 и не включает обработку входящих пакетов.

Семантика маркера:

- Он является явным утверждением пользователя, что **данное правило**
  использует очередь управляемого Trafira провайдера, а не другой программы.
  Проверка не доказывает принадлежность слушателя и не проверяет стратегию.
- Учитывается только самостоятельный конечный `comment "trafira-ignore"`
  в строке правила из `nft list ruleset`. Подстроки, дополнительные слова,
  другой регистр, экранированная запись и некорректные кавычки не подходят.
- Исключение действует только на правило с одним `queue` и статическим
  номером либо возрастающим диапазоном очередей **целиком внутри**
  проверяемого диапазона провайдера. Номера должны быть в пределах 0–65535.
  Наборы, динамические выражения, несколько statements в строке и диапазоны,
  пересекающие границу диапазона провайдера, исключения не получают.
- Маркер не распространяется на соседние правила, всю цепочку или `inet fw4`.
  Немаркированное правило для той же очереди по-прежнему вызывает конфликт.
  Текст комментария не анализируется как выражение `queue`.

Для zapret2 диапазон по умолчанию — 4300–4555. Совпадение номера с этим
диапазоном само по себе не означает принадлежность Trafira. Используйте
маркер только после проверки, что номер соответствует нужной активной
секции и правилом действительно пользуется её nfqws2. После изменения
конфигурации секций проверьте это соответствие снова: маркер не связывает
правило с именем секции и не переназначает номер автоматически.

Диагностика правил проверяет канонический текст `nft list ruleset`, а не
синтаксическую корректность исходного `.nft` файла; её проверяет nft/fw4 при
загрузке. Исключение не отключает прочие проверки готовности провайдера.
